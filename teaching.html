Teaching philosophy

Theory first, then the working system. Students should not only be able to derive the result — they should be able to build it, simulate it, measure it, and explain why it behaves the way it does.

A VLSI subject makes that concrete. Designing a memory cell and then simulating it in H-SPICE teaches the physics of the device, the limits of the model, and the trade-off between power, area and delay — in a way a lecture alone cannot.

Learning outcomes & assessment

  • Outcome-based design. Course outcomes are written as measurable statements and mapped to the assessment plan.
  • Continuous assessment. Internal assessment, laboratory work, quizzes and end-semester examination.
  • Autonomous learning. Project work that takes students beyond the prescribed syllabus.
  • Industry alignment. Seven years in the software industry shapes the application-oriented parts of the syllabus — version control, code review, testing and release discipline.

The differentiator: software engineering is taught here not only as theory, but by someone who has run sprints, reviewed code and shipped releases to paying customers. Very few academics can say that with the same authority.

AI in the classroom & beyond

A substantial part of my current work is training others on AI development tools — first as an academic responsibility, then extending it to faculty and industry.

Students

AI workshops for UG & PG

Hands-on sessions using Claude, Cursor, Gemini and ChatGPT for VLSI and software work: Verilog and HDL generation, simulation scripting, debugging, literature summarisation and test case design. Every output must be verified before it is accepted.

Faculty

Faculty development sessions

Practical training on preparing laboratory manuals, designing assignment problems and question banks, and generating documentation — while keeping assessment integrity and academic standards intact.

Industry

Consulting for teams

Bringing AI-assisted development into real delivery: legacy code comprehension, structured refactoring, test generation and documentation, applied with the code review discipline my industry years give me.

Why this fits an ECE department: the value is not that AI writes code faster. It is that a student learns to specify a problem precisely, evaluate a confident answer, and reject a wrong one — the same discipline a VLSI design verification course is meant to build.
